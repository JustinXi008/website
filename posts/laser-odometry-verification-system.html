Laser Odometry Verification

A background positioning system that uses VEX V5 distance sensors, field geometry, and careful filtering to keep a robot’s odometry aligned.

April 5, 2026 Completed

Wheel encoders and an inertial measurement unit can estimate a robot’s movement with high precision, but that estimate is still relative. Small errors from wheel slip, impacts, or sensor noise accumulate throughout a match. A tiny tracking error early in an autonomous run can become a large positional offset by the end.

The odometry drift problem

Standard odometry integrates many small changes in position. Because every new pose is calculated from the previous one, it has no absolute reference with which to catch a growing error. Resetting once at the start helps, but it cannot correct drift introduced after the robot begins moving.

I built Laser Odometry Verification (LOV) to provide that reference. It uses the known perimeter of the field and readings from VEX V5 distance sensors to estimate an absolute coordinate, then compares that result with the robot’s tracked pose.

The core idea

Odometry predicts where the robot moved. LOV measures where the field says the robot is, then uses that measurement to correct the prediction.

How LOV improves odometry

Continuous background syncing

VOLMain.startTracking() runs as a background task. It continually calculates a pose from sensor data and, when autoSync is enabled, sends validated corrections to the chassis position-tracking object.

Noise reduction

Distance readings naturally fluctuate. When the robot is stationary, an accumulation routine averages a set of samples to establish a more reliable baseline coordinate.

Configurable filtering

minDelta ignores insignificant changes caused by normal sensor noise, while maxDelta rejects implausible jumps that may come from a field element or another robot. maxSyncPerSec limits how frequently a correction may be applied.

Efficient sensor use

The system sits between uncorrected odometry and a more complex localization stack. It uses inexpensive distance sensors and known wall positions to improve absolute accuracy without introducing a full LiDAR solution.

Implementation

At its core, LOV is a geometric ray-casting system. Each distance sensor is treated as a ray that begins at a known point on the robot and extends along the sensor’s heading until it reaches the field perimeter.

1. Locate the sensor on the field

A sensor is mounted at a fixed distance and angle from the robot’s tracking center. As the robot turns, that offset rotates with it. Given the robot pose (xbot, ybot, θbot), sensor offset distance doffset, and offset angle θoffset, LOV first calculates the sensor’s absolute origin:

xsensor = xbot + cos(θoffset − θbot) · doffset ysensor = ybot + sin(θoffset − θbot) · doffset

2. Intersect the ray with a wall

Once the sensor origin and heading are known, LOV projects the ray toward the field’s known boundaries. The measured distance D is resolved into its X and Y components. If the ray reaches a wall parallel to the Y-axis, for example, the field X-coordinate can be recovered from the wall position and the ray angle α:

Xfield = WallX − cos(α) · D

The equivalent calculation is used for a horizontal wall and the Y-coordinate. LOV then translates the wall-derived sensor coordinate back to the robot’s geometric center, producing a candidate absolute pose.

3. Reject obstructed readings

A distance sensor does not know whether it is looking at a wall, a goal, or another robot. LOV lets field elements be declared as Line_Obstacle and Circle_Obstacle zones. Before accepting a measurement, it checks the sensor ray against these known obstacles.

Line intersections are evaluated with parametric equations; a cross-product test determines whether an obstacle lies between the sensor and the expected wall. If it does, the reading is invalidated before it can corrupt the robot’s pose.

Result

LOV turns the field perimeter into a recurring absolute reference. The robot can continue using fast, responsive wheel-and-IMU odometry for motion while verified distance readings quietly constrain long-term drift in the background.
